# esa-cli 1.0.14-beta.1

## Changes

- Accounts with a new compute plan can log in and deploy as soon as ESA reports the subscription as purchased. Accounts without a new subscription can continue using an active legacy edge routine service.
- Login and deployment report which account check failed. When the legacy service is still activating, the CLI prompts you to retry later.
- Beta builds now prompt for updates only when a newer beta is available. Stable builds follow the `latest` channel.
- URLs containing `//` are preserved when reading `esa.jsonc`. Workers can use the cache API during `esa dev` on Windows.
- Unknown top-level commands now exit with status 1. The help text shows the full commands for `esa project list`, `esa project delete`, and `esa site list`. Use `esa domain add -h` for domain binding help.

## Compatibility

Node.js 18 or later is supported. Existing projects can keep their configuration and login commands. If you use a custom RAM policy, allow `esa:GetSubscriptionPlan` even for accounts using the legacy service. If this query is denied, validation stops. When it returns `Purchased: false`, the CLI also requires `esa:GetErService` and accepts the legacy service when its status is `Running`.
