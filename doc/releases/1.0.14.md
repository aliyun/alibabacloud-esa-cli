# esa-cli 1.0.14

## Changes

- `esa login`, `esa deploy`, and other commands that check account access accept a purchased compute plan. If ESA reports no purchase, the CLI accepts the legacy Functions and Pages service when it is running. If the service is still activating, the CLI asks you to retry later.
- Update prompts follow the installed channel. Stable installations check `latest`, and beta installations check `beta`. The CLI prompts only for a newer version.
- The CLI preserves URLs containing `//` in `esa.jsonc`. Workers can use the cache API during `esa dev` on Windows.
- Unknown top-level commands exit with status 1. Usage examples for `esa project list`, `esa project delete`, and `esa site list` show the full command. Use `esa domain add -h` for domain binding help.

## Compatibility

Node.js 18 or later is supported. If you use a custom RAM policy, allow `esa:GetSubscriptionPlan` for both new and legacy accounts. If that query is denied, the CLI reports the failed query and stops validation. Legacy accounts also need `esa:GetErService` so the CLI can check the existing service.
