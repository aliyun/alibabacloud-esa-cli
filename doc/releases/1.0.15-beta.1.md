# esa-cli 1.0.15-beta.1

## Changes

- Add `esa deploy --output=json` for automated deployments. Stdout contains one JSON document with `schemaVersion: 1`, the application name, a token-free URL, and per-environment deployment IDs and code versions. Progress and diagnostics go to stderr; `text` remains the default output format.
- Flush deployment output before exiting, including when unrelated handles keep the process alive. Deployment failure exits with status 1 and retains any successfully published environments in the JSON result.
- Report launcher startup failures to stderr with a non-zero exit status. Keep `init --deploy` and weighted deployment callers compatible with structured deployment results.

## Compatibility

- Requires Node.js 18 or later. Built on esa-cli 1.0.14; the URL-safe JSONC parser, compute-plan validation, credential handling, and proxy support remain in place.
- Deployment still defaults to production. Use `--environment staging` explicitly for staging. When both environments are needed, create and deploy a version separately for each environment; existing environment-binding checks still apply.
- JSON mode does not fetch or include a temporary access token. A failed preview URL lookup or `--no-preview` sets `url` to null without changing deployment success. `deploymentId` may also be null.
- Check the process exit status before using stdout. Parser failures and unexpected exceptions may report only to stderr.
- Consumers upgrading from 1.0.12-beta.2 can retain the version-1 JSON contract. Their custom RAM policies or service-linked role policies must also cover `esa:GetSubscriptionPlan` and `esa:ListRoutineCodeVersions`; legacy accounts continue to need `esa:GetErService`.
